# 智能烹饪技能设计文档

## 概述

基于 [HowToCook](https://github.com/Anduin2017/HowToCook) 开源项目，构建一个智能烹饪技能。支持语义化菜谱推荐、营养信息查询、食材反推、定时同步等功能，帮助用户解决"今天吃什么"的日常问题。

## 核心模块

### 1. 数据索引构建 - `build_index.py`

**职责**：从 HowToCook GitHub 仓库抓取所有菜谱，构建本地 JSON 索引。

**功能**：
- 抓取所有菜谱的 Markdown 文件
- 提取元数据：菜名、分类、难度星级、食材列表、做法摘要
- 通过营养估算模型自动计算营养数据
- 输出 `recipes_index.json`

**菜谱分类**：
- 素菜 (vegetable_dish)
- 荤菜 (meat_dish)
- 水产 (aquatic)
- 早餐 (breakfast)
- 主食 (staple)
- 半成品加工 (semi-finished)
- 汤与粥 (soup)
- 饮料 (drink)
- 酱料 (condiment)
- 甜品 (dessert)

### 2. 营养估算模型 - `nutrition_db.json` + `nutrition_calculator.py`

**职责**：为每道菜自动估算营养数据。

**营养数据结构** (`nutrition_db.json`)：
```json
{
  "西红柿": {"calories": 18, "protein": 0.9, "carbs": 3.9, "fat": 0.2, "unit": "per_100g"},
  "鸡蛋": {"calories": 144, "protein": 13.3, "carbs": 2.8, "fat": 8.8, "unit": "per_100g"},
  "鸡胸肉": {"calories": 133, "protein": 24.6, "carbs": 0, "fat": 2.0, "unit": "per_100g"}
}
```

**辣度推断规则**：
- 0 级：无辣（默认）
- 1 级：微辣（含少量辣椒/可选辣）
- 2 级：小辣（青椒/红椒）
- 3 级：中辣（干辣椒/辣子）
- 4 级：重辣（麻辣/小米辣/泡椒）
- 5 级：特辣（变态辣/魔鬼辣）

**营养计算方式**：
- 根据菜谱中食材用量 × 每 100g 营养值
- 无法解析用量时使用默认份量估算
- 可选调用外部营养 API（如 Nutritionix）补充

### 3. 技能交互层 - `chef_skill.py`

**职责**：处理用户语义化询问，返回菜谱推荐或详情。

**支持的询问模式**：

| 询问类型 | 示例 | 返回 |
|---------|------|------|
| 随机推荐 | "今天吃什么" | 按人数+场景+营养推荐组合 |
| 简单/快手 | "想吃点简单的" | 筛选 1-2 星难度 |
| 辣度筛选 | "想吃辣的" / "不吃辣" | 按辣度过滤 |
| 卡路里筛选 | "想吃低卡的" | 按卡路里阈值过滤 |
| 饮食模式 | "来点低脂餐" / "素食" | 按标签过滤 |
| 具体菜查询 | "宫保鸡丁怎么做" | 完整菜谱+做法 |
| 营养查询 | "西红柿炒鸡蛋多少卡路里" | 营养信息 |
| 食材反推 | "家里有鸡蛋、西红柿" | 反推可做的菜 |
| 购物清单 | "推荐几道菜，我要去买菜" | 推荐+购物清单 |

**推荐策略**：

按人数搭配：
- 1-2 人：1 荤 + 1 素（或 1 主食 + 1 菜）
- 3-4 人：2 荤 + 1 素 + 1 汤
- 5-6 人：3 荤 + 2 素 + 1 汤 + 1 甜品/饮料

按场景搭配：
- 工作日：推荐 30 分钟内可完成的菜（难度 1-2 星）
- 周末：可推荐复杂菜式（难度 3+ 星）

季节性推荐：
- 春：清淡、时令蔬菜
- 夏：凉拌、清蒸、冷菜
- 秋：润燥、煲汤
- 冬：炖菜、红烧、热汤

### 4. 食材反推引擎

**职责**：根据用户提供的食材列表，匹配可做的菜谱。

**流程**：
1. 用户说出家中食材（如"鸡蛋、西红柿、豆腐"）
2. 匹配 `recipes_index.json` 中所需食材被满足的菜
3. 按匹配度排序（所需食材覆盖率高的优先）
4. 如用户未提供食材信息，用 `AskUserQuestion` 主动询问

### 5. 购物清单生成

**职责**：为推荐菜式生成采购清单。

**输出格式**：
```
【今日推荐】宫保鸡丁 + 清炒花菜 + 紫菜蛋花汤
-----------------------------------------
需要购置：
- 鸡胸肉 200g
- 花生 50g
- 干辣椒 10g
- 花菜 1 颗
- 紫菜 5g
- 鸡蛋 2 个
- 葱、姜、蒜（如家中没有）
```

### 6. 定时同步 - `sync_recipes.py`

**职责**：定期从 HowToCook 仓库拉取更新。

**功能**：
- 对比本地索引与远程菜谱差异
- 增量更新新菜谱
- 新菜谱自动通过营养估算模型补充数据
- 支持 Cron 定时执行
- 更新完成后静默保存

## 优化特性

### 1. 季节性推荐
根据当前月份自动调整推荐权重：
- 3-5 月（春）：清淡、时令蔬菜权重 +20%
- 6-8 月（夏）：凉拌/清蒸权重 +30%，热汤权重 -10%
- 9-11 月（秋）：煲汤/润燥权重 +20%
- 12-2 月（冬）：炖菜/红烧/热汤权重 +25%

### 2. 菜品去重/组合去重
推荐组合时避免主要食材重复：
- 不会同时推荐两道都大量使用鸡蛋的菜
- 不会推荐两道都用同一种肉类的荤菜

### 3. 烹饪时间估算
根据难度星级和步骤数估算总时长：
- 1 星：5-15 分钟
- 2 星：15-25 分钟
- 3 星：25-40 分钟
- 4 星：40-60 分钟
- 5 星：60+ 分钟

### 4. 口味偏好记忆
通过对话记录用户喜好：
- 用户说"不喜欢吃辣" → 后续默认过滤辣度 > 2
- 用户说"这个好吃" → 标记为喜欢，提升同类推荐权重
- 偏好数据存储在 `user_preferences.json`

## 技术选型

- **语言**：Python 3
- **数据格式**：JSON
- **依赖**：requests（HTTP 请求）、json（数据序列化）
- **定时任务**：通过 Schedule 工具配置 cron 执行 `recipe_sync.py`
- **抓取方式**：GitHub REST API + 原始文件直链（`raw.githubusercontent.com`）

## 同步机制细节

### 增量更新策略

- 对比本地 `recipes_index.json` 与远程目录结构
- **新增菜谱**：下载 Markdown，解析元数据，计算营养，追加索引
- **删除菜谱**：远程不存在但本地有的，标记为 `deprecated`，30 天后清理
- **重命名菜谱**：通过内容 hash 检测移动/重命名，更新路径映射

### GitHub API 频率控制

- 使用 raw 文件直链抓取（无需 API token，无频率限制）
- 目录结构通过 GitHub API 获取（未认证 60 次/小时）
- 本地缓存目录结构，仅在有更新时重新拉取

## 营养数据来源

1. **内置数据库**：基于公开营养数据库整理常见食材营养值
2. **外部 API（可选）**：Nutritionix API 查询补充
3. **估算模型**：根据食材名称和用量自动计算

## 错误处理

- 网络请求失败：使用本地缓存的索引数据
- 营养数据缺失：标记为"估算值"，提示用户
- 菜谱解析失败：跳过该菜谱，记录日志
- 食材无法匹配：使用模糊匹配（编辑距离 ≤ 2）
